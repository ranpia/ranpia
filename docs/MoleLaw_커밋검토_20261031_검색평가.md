# MoleLaw 2026-10-31 검색 평가 검토

검토일: 2026-10-31. 개인 포크 `ranpia/MoleLaw_backend`의 실험 브랜치 최신 커밋 `3d9a7abfc75d622c97c1df511a27853d5537ad79`와 그 부모 대비 변경을 확인했다. 검토 경로는 `.tools/MoleLaw_review`이며 `git show`로 코드·실행 계약·보고서·집계 원자료를 읽었다. 이번 문서 검토에서 모델·서버·Qdrant 호출 또는 실험 재실행은 하지 않았다. 결과는 저장된 실행 기록과 집계 코드의 대조에 근거한다.

원격 이력이 재작성되어 10월 23일 기록의 해시를 최신 브랜치의 직계 조상으로 가정하지 않는다. 이전 커밋 검토는 당시 기록으로 보존하고, 이번 근거 링크는 최신 확인 리비전에 고정한다. 팀 개발의 담당 범위와 별개인 2026년 개인 재구축·평가 경험이다.

## 문제에서 다음 선택으로 이어진 흐름

이전 평가에서는 KURE 500자·법률 쟁점 변환 질의의 상위 50개 후보에 필요한 근거가 모두 있는 질문이 11/36개에 그쳤다. 따라서 검색 후보를 잘 정렬하는 문제와 후보 자체에 근거가 없는 문제를 구분할 필요가 있었다.

이번 커밋은 두 실험을 추가했다. 먼저 동일한 후보 50개를 고정하고 현재 서비스의 BGE 리랭커가 순위를 바꾸는 효과를 측정했다. 정답 하나 이상을 상위 5개에 넣는 질문은 늘었지만 필요한 정답 전체를 넣는 질문 수는 같았다. 이어 현재 근거 수집 코드로 최초 검색과 추가 검색 허용 후 종료 시점을 같은 실행 안에서 비교했다. 이때 실제 추가 검색한 8문항 모두 최초 후보 집합 밖의 정답 근거를 새로 회수했다.

사용자가 공유 대화에서 설명한 리랭커 도입 판단은, 상위5개와 더 넓은 후보 범위의 회수율 차이를 보고 정답이 뒤쪽에 밀렸다고 생각했다는 것이다. 당시 상위 후보 수는50인지100인지 기억이 불확실하므로 정확한 당시 비교값으로 만들지 않는다. 이번 코드·보고서에서 확인되는 비교 범위는50개다.

확인 가능한 판단은 **후보 내부 순위 개선과 후보 외 근거 회수를 분리해 검증했다**는 점이다. 개발자의 당시 감정이나 문서·설명에 없는 의도는 추정하지 않는다. 두 실험의 수치를 곧바로 더하거나 빼서 리랭커와 반복 검색의 기여도를 계산하지 않는다.

## 1. 고정 dense 후보 50개에 대한 리랭킹 비교

| 단계 | 확인 내용 |
| --- | --- |
| 문제 | 필요한 법령이 후보에 있어도 상위 5개에 배치되지 않는 경우와 후보 밖에 없는 경우를 구분해야 한다. |
| 판단 기준 | Hit@5와 Complete@5를 공동 우선으로 보고 질문별 개선·악화를 함께 확인한다. 후보 밖 정답을 리랭커가 회수한 것으로 계산하지 않는다. |
| 선택 | 기존 36문항·고정 정답·KURE-v1·500자·중복64자·법률 쟁점 질의·dense50 후보·대표 청크를 유지하고 BGE cross-encoder로 순서만 바꾼다. |
| 측정 | Hit@5 20→22/36, Complete@5 4→4/36, Recall@5 31.39→38.19%. |
| 남은 문제 | 일부 순위는 개선됐지만 필요한 근거 전체 확보는 증가하지 않았다. 후보 회수 단계와 재정렬 단계의 후속 실험을 구분해야 한다. |

현재 리랭커는 `BAAI/bge-reranker-v2-m3`, revision `953dc6f6f85a1b2dbfca4c34a2796e7dde08d41e`다. 제목과 대표 청크를 입력으로 사용하며 CPU float32·배치2·최대1024토큰 조건을 유지했다. 원시 cross-encoder 점수와 cosine 점수를 합치거나 임계값으로 결과를 제거하지 않았다. dense cosine 점수와 후보 ID는 보존하고 동점은 기존 순위를 유지했다.

최종 완료 실행은 `reports/20261031T011428Z`다. 1문항 smoke 실행을 전체36문항 결과와 섞어 별도 표본으로 세지 않는다.

| 지표 | 적용 전 | 적용 후 | 해석 |
| --- | ---: | ---: | --- |
| Hit@5 | 20/36 (55.56%) | 22/36 (61.11%) | 3문항 개선·1문항 악화 |
| Complete@5 | 4/36 (11.11%) | 4/36 (11.11%) | 2문항 개선·2문항 악화로 총수는 같음 |
| Recall@5 | 31.39% | 38.19% | 반올림 전 차이 +6.81%p, 질문별8개 개선·2개 악화 |
| nDCG@5 | 0.2651 | 0.3943 | 여러 정답의 상위 배치 개선 |
| MRR@10 | 0.3421 | 0.5347 | 10위 밖 첫 정답은0점인 지표 |
| Recall@50 | 56.57% | 56.57% | 고정 후보 집합이므로 동일 |

전체 정답이 후보50 안에 있는 질문은11/36, 정답이 하나라도 있는 질문은30/36이다. 동일 후보만 재정렬할 때 Complete@5와 Hit@5의 이론상 상한도 각각11/36·30/36이다. 정답 수가5개를 넘는 등 개별 조건에 따라 실제 달성 상한은 더 제한될 수 있으므로 일반적인 달성 보장으로 쓰지 않는다.

회귀 사례도 남았다. `ind-003`의 고정 정답은2위에서6위로 내려가 Hit@5·Complete@5가 모두 악화됐다. `ind-032`는 기존 정답 순위1·2·3위가1·2·6위가 되어 일부 정답을 놓쳤다. 반대로 `ind-046`은6·9위의 정답이2·4위가 되어 두 지표가 개선됐다. 이는 고정 정답 순위이며 법률 판단의 정오를 검증한 결과가 아니다.

리랭커 HTTP 시간은 평균33.09초·p50 30.97초·p95 66.12초·최대87.73초다. 36응답 중1개는 사전 smoke 캐시와 최초 측정 시간을 재사용하고35개는 본 실행 추론이다. 서비스 읽기 제한120초와 별개로 실험 HTTP 제한은300초였다. dense 검색·답변 생성·동시 부하를 포함하지 않아 운영 SLA나 전체 서비스 응답 성능으로 표현하지 않는다.

## 2. 동일 실행의 최초 후보와 반복 검색 종료 후보 비교

| 단계 | 확인 내용 |
| --- | --- |
| 문제 | 리랭커는 고정 후보 밖 근거를 가져오지 못한다. 서비스의 추가 검색과 누적이 이 한계를 보완하는지 확인한다. |
| 판단 기준 | 같은 실행의 최초 후보와 종료 후보를 비교해 초기 LLM 분석의 무작위 차이를 조건 차이로 오인하지 않는다. 실패 문항도 전체 분모에 포함한다. |
| 선택 | 현재 질문 계획·근거 읽기·판단·수집 코드와 리랭커를 유지하고 최대4회 추가 행동을 허용한다. 외부 수집은 금지하고 기존 Qdrant 코퍼스를 사용한다. |
| 측정 | 36문항에서 Hit@15 19→26, Complete@15 5→8. 추가 검색8문항 모두 최초 dense 후보 집합 밖의 정답을 종료 후보에 포함했다. |
| 남은 문제 | 질문 분석5문항 실패, 행동 소진 후 근거 부족1문항 실패. 종료 후보에 정답이 있어도 최종 선택에서 빠진 사례가 있다. 답변 생성은 평가하지 않았다. |

최종 완료 실행은 `full-serviceids-20261031`이다. `smoke*`, `full-20261031`, `full-canonical-20261031` 등 준비·중단 자료는 최종36문항 지표에 합산하지 않는다.

고정 질문·정답은 이전 탐색에 사용한 코퍼스 내36문항이다. 500자 코퍼스8,286청크와 KURE1024차원·리랭커는 유지하지만, 검색 질의는 과거 고정 법률 쟁점 변환문 대신 실제 질문 분석기가 새로 생성한다. 최초 배치도 여러 쟁점 질의를 허용한다. 각 질의는 최대 dense50을 검색하고 리랭커가 최대15개를 반환하며, 쟁점 균형·RRF·누적 보존을 거친 최대15개 후보 풀을 평가한다. 특정 법령·조문을 지정한 질의는 해당 조문으로 제한하므로 반환 수가50보다 적을 수 있다.

| 전체36문항 지표 | 최초 검색 배치 후 | 반복 허용 종료 시 |
| --- | ---: | ---: |
| Hit@15 | 19/36 (52.78%) | 26/36 (72.22%) |
| Complete@15 | 5/36 (13.89%) | 8/36 (22.22%) |
| Recall@15 | 32.04% | 45.93% |
| Hit@5 | 27.78% | 50.00% |
| Complete@5 | 5.56% | 13.89% |
| Recall@5 | 14.58% | 28.70% |

초기 질문 분석 실패5문항은 최초·종료 후보가 없어 양쪽0점이다. 최초 후보를 확보한31문항만 보면 Hit@15 61.29→83.87%, Complete@15 16.13→25.81%이지만 이 조건부 결과로 전체 성능을 대체하지 않는다.

검색은 최초40회·추가42회, 총82회였다. 그중 조문 지정 조회18회, 문항당 최대13회다. 추가 검색은8/36문항에서 실행됐으며 Hit@15는7문항 개선·0문항 악화, Complete@15는3문항 개선·0문항 악화였다. 이8문항의 종료 풀에는 각각 최초 배치의 모든 dense 후보를 합친 집합 밖의 고정 정답이 포함됐다. 후보 순서 변경만으로 설명할 수 없는 회수 결과다.

## 새로 확인한 실패와 평가 경계

정상 근거 수집은30문항이며 `ANSWER_READY`12개·`ANSWER_PARTIAL`18개다. 실패는 질문 분석 계약·출처 검증5개와 추가 행동을 모두 소진한 근거 부족1개다. 외부 수집 요청에 따른 중단은 이번 실행에서는 없었다.

종료 후보는 사용자에게 전달한 근거와 다르다. 실패 문항을0점으로 처리하고 정상 선택한 근거만 계산하면 Hit는25/36(69.44%), Complete는7/36(19.44%), 평균 Recall은44.07%다. `ind-010`은 종료 풀에 정답3개가 있었지만 최종 선택은2개만 포함했고 상태는 `ANSWER_READY`였다. **준비 상태가 고정 정답 전체 확보를 보장하지 않으며, 회수·읽기/선택·답변 검증을 분리할 이유**가 확인됐다. 최종 답변 생성·인용 검증·채팅방 저장은 실행하지 않았다.

최초 후보 확보31문항의 평균 최초 시간34.49초, 전체 근거 수집73.92초다. 전체36문항 평균64.75초, 최대331.71초였다. 최초 시간에 충분성 판단이 포함되지 않으므로 차이를 추가 검색만의 순수 비용으로 쓰지 않는다. 이 결과는 한 번의 실제 LLM 실행이며 반복성·통계적 확실성·서비스 전체 지연 보장이 아니다.

Java 실행기는 현재 서비스의 `LegalEvidenceCollector`, `QuestionRetrievalPlanner`, `EvidenceDecisionPlanner`, `EvidenceReadPlanner`, `LawRerankerClient`를 사용하되 SQL 색인·원문 저장소 경계는 고정 코퍼스 어댑터로 교체했다. 원문 청크 겹침을 검사해 본문을 복원하고 서비스 형식ID와 평가 정답ID를 일대일 변환한다. 따라서 실제 SQL 공개·복원 흐름 전체의 종단간 검증은 아니다. 고정 코퍼스는 별표·고시를 포함해 현재 서비스 본문 색인 범위와도 차이가 있다.

추론의 질문 분석·근거 읽기에는 `gpt-5.4-mini`, 판단에는 `gpt-5.4`를 사용한 실행 설정이 보존돼 있다. 정답은 집계에만 사용하고 모델에 제공하지 않았다. 실험은 공급자 오류 자동 재시도를 끄므로 서비스 기본 재시도와 완료율 조건이 다르다. 외부 OpenLaw 수집·ETL·색인 쓰기는 금지했고 후속 판례 흐름은 포함하지 않았다.

원본 소스·프롬프트236개, 빌드 관련6개, 실험 입력5개 등의 해시와 소스 스냅샷 기록이 있다. 당시 작업 트리에 미커밋 변경이 있어 보고서의 원본 HEAD만으로 실행 코드를 동일하게 재현했다고 단정하지 않는다. 이번 검토에서도 서비스 전체 코드를 이 실험 커밋만으로 재현한 것은 아니다.
