# MoleLaw 의사결정과 커밋 근거

확인일: 2026-10-23. 개인 앱 `dev=7962c442e8b9a355f190852d3746c4046db748f8`, 실험 `bd2ae9440f3f2d8253034c73b6e5e972e5091a3c` 기준이다. 코드·문서·저장된 결과를 읽었으며 모델·서버·프로젝트 테스트를 실행하지 않았다. 기록된 선택과 변경을 정리한 문서이며 당시의 심리나 혼자 내린 결정까지 추정하지 않는다.

2025년 팀 개발에서 본인의 주 담당은 RAG였고 FinalAnswer는 팀원과 같은 화면을 보며 공동 개발·수정했다. 인증 등 다른 기능은 통합·수정·논의 기여가 중심이다. 아래 2026년 개인 재구축과 구분한다.

## 1. 높은 점수보다 새로운 질문에서 필요한 근거를 찾는지 확인

**관찰:** 초기 모델·청크 비교와 확대 검증에서 높은 검색 점수가 나왔다. 하지만 질문·정제본을 공식 원문을 보며 작성한 평가라 새로운 사용자 질문을 처리할 수 있는지까지 확정할 수 없었다.

**판단 기준:** 모델 간 원시 유사도 대신 정답 근거의 회수율과 순위를 비교하고, 질문 작성과 정답 검토를 분리해 기존 평가 조건 밖에서도 확인한다. 관련 근거를 하나 찾은 경우와 모두 확보한 경우를 구분한다.

**선택:** KURE를 검색 기준 모델로 보존하면서 별도 100문항을 고정했다. 이후 이 자료로 임계값·질의를 조정한 시점부터는 튜닝 자료로 취급해 독립 검증 자료로 재사용하지 않기로 기록했다.

**확인 결과:** 코퍼스 내 36문항의 Recall@5는 원본 14.12%·정제 16.44%, Complete@5는 모두 3/36이었다. 이전 확대 평가 99.17%와는 표본·정답·질문 생성 조건이 달라 같은 조건의 성능 하락으로 비교하지 않는다. 임계값을 낮춰도 검색 순위는 개선되지 않았고 범위 밖 질문 수용도 함께 증가했다. 질의 변환·청크 길이·상위 50개 후보 회수를 추가 비교했다. 서비스 품질 합격은 보류하고 추가 검색 전략을 계획했다.

**남은 조건:** 법률전문가가 확인한 완전한 정답 집합은 아니다. 정답 밖의 관련 조문도 있을 수 있으며 후속 개선은 새로운 평가 자료로 확인해야 한다. 검색 점수는 답변 정확도·탈옥 방어율이 아니다.

근거: `1255f63`·`ffaa4d2`·`6efbabf`·`4413496`·`64c98fc` 및 [실험 커밋별 검토](MoleLaw_커밋검토_실험.md).

## 2. 상담이 호출 한도에서 끝나면 어떤 작업이 예산을 썼는지 구분

**관찰:** 실상담에서 공항시설법 228청크를 색인·검증하고 15조문을 재검색한 뒤, 다음 법령 색인 중 공유 HTTP 128회 한도가 소진됐다. 첫 답변·상담방 저장의 성공은 기록되지 않았다.

**판단 기준:** 검색·수집과 임베딩·색인은 호출량이 달라 한 카운터가 서로의 예산을 소진하게 해서는 안 된다. 한도를 없애거나 법령마다 초기화하면 요청 전체의 실행 상한이 무너진다.

**선택:** 용도별 HTTP 카운터를 분리해 실행 전체에서 각각 누적하고, 벡터·모델 검증과 완료 세대 공개 조건을 유지했다. 모델 revision 확인은 색인 세션 첫 배치에서 하고 실패 후에는 재검증하도록 했다.

**확인 결과:** 128회를 넘는 합성 조문 적재·누락 복구·재검색이 대역·격리 Qdrant 테스트에서 통과했다. 수정 후 같은 실상담의 성공까지 확인한 결과로 쓰지 않는다.

근거: `2225a12`, [서비스 커밋별 검토](MoleLaw_커밋검토_서비스.md), [검증 기록](https://github.com/ranpia/MoleLaw_backend/blob/7962c44/docs/validation-status.md).

## 3. 검색 후보 목록과 읽은 근거를 구분해 판단에 전달

**관찰:** 제한된 입력에 본문을 담는 방식과 이미 읽은 근거를 다시 선택할 때 실패하는 경로를 보완했다. 실제 요청의 원시 모델 응답이 없어 특정 실요청의 예외 원인까지 확정하지 않는다.

**선택:** 후보 목록을 먼저 비교해 서버가 허용한 ID의 원문만 읽고, 실제 읽은 본문으로 충분성을 판단하도록 분리했다. 목록·본문·결합 입력의 상한을 따로 두고, 이미 읽은 ID 재선택은 건너뛰어 기존 본문을 보존한다. 목록에만 있는 ID를 답변 근거로 승인하지 않는다.

**확인 결과와 제약:** 미등록 ID·원문/버전 불일치·읽지 않은 ID 승인 차단과 재선택 회귀를 확인한 기록이 있다. 모든 관련 법령의 회수나 법적 충분성을 입증한 것은 아니며 항 단위 읽기·참조조문 확장은 후속 과제다.

근거: `2225a12`, [본문 읽기 계약](https://github.com/ranpia/MoleLaw_backend/blob/7962c44/docs/evidence-reading.md).

## 4. 대화를 기억하는 기능과 외부 판례를 조회할 권한을 분리

**관찰:** 후속 상담에는 대화 맥락과 검증 가능한 원문 근거가 모두 필요하다. 동의 요청 문구에 인용이 없어 실패하는 경로도 검증 기록에 남아 있다. Tool·추론 옵션 조합 거절은 코드 주석과 설정 변경으로 확인하며 실요청의 오류 로그와 동일시하지 않는다.

**선택:** MessageChatMemoryAdvisor는 대화 기록만 복원하고 최초 법령 근거는 별도로 고정한다. 요청의 `allowCaseSearch=true`일 때만 외부 판례 검색 도구를 노출하며 서버에서도 검사한다. 대화의 ‘네’나 과거 동의를 새 요청의 권한으로 사용하지 않는다. 동의 요청은 서버가 방의 법령 근거 UUID를 포함한 질문으로 구성한다. 판례 인용은 실제 읽은 판례 ID만 허용하고 실패한 턴은 저장하지 않는다.

**확인 결과와 제약:** 합성 모델·판례 자료를 이용한 통합 테스트에서 동의 전 외부 호출 0회, 승인 후 검색·본문·인용·저장과 기존 판례 재사용을 확인했다. 실판례 답변의 관련성·법적 타당성, 브라우저 승인 UI·동시 턴·탈옥 방어는 추가 검증 대상이다. Advisor 자체를 보안 차단 기능으로 설명하지 않는다.

근거: `6d08181`·`0a6a361`·`1f43103`, [후속 상담 커밋별 검토](MoleLaw_커밋검토_후속상담.md).
