## 프로젝트 원자료와 검토 기록

- **MoleLaw 팀 프로젝트** · [원자료 폴더](molelaw)에는 발표자료와 초기 설계 문서가 있습니다. 서비스 목표와 당시 상담 흐름을 확인할 때는 [팀 발표 PDF](molelaw/MoleLaw%20%281%29%20%281%29.pdf) 7·20쪽, 초기에 구상한 책임과 흐름은 [LawMate 설계](molelaw/LawMate_Architecture.pdf)를 참고합니다.
- **MoleLaw 개인 재구축** · [검색 평가](MoleLaw_커밋검토_20261031_검색평가.md), [부하 시험](MoleLaw_커밋검토_20261031_부하검증.md), [상담 흐름](MoleLaw_커밋검토_20261031_상담흐름.md)에 조건과 결과가 있습니다. 이전 변경의 근거는 [서비스](MoleLaw_커밋검토_서비스.md), [실험](MoleLaw_커밋검토_실험.md), [후속 상담](MoleLaw_커밋검토_후속상담.md) 검토에서 찾을 수 있습니다. 브랜치 기준은 각 문서의 검토 시점을 따릅니다.
- **Molecom** · [원자료 폴더](molecom)에는 아이디어 메모와 발표자료가 있습니다. [발표자료](molecom/molecom.pdf) 14–16쪽에서 검사 검색·과거 검사 이력·Study Report 화면을 확인할 수 있습니다. 초기 구상에는 의료 영상의 저장·조회 흐름과 판독 보조 결과를 작업 목록에 표시하는 아이디어가 있었습니다. 검사와 리포트의 관계는 [본인 커밋](https://github.com/24Sahmyook-Team-s1/Molecom_backend/commit/8f2c4eb), 계정 삭제 구현은 [팀원 커밋](https://github.com/24Sahmyook-Team-s1/Molecom_backend/commit/5a59574)을 근거로 삼습니다.
- **AI Diary** · 별도 발표 원자료와 함께 확인할 내용은 본인 역할과 당시 판단입니다. 현재 구현 근거는 [후속 가입](https://github.com/AIDiaryET/AI_Diary-backend/commit/049a131), [상담기관 검색·수집](https://github.com/AIDiaryET/AI_Diary-backend/commit/d273e08)입니다.

## 다음 할 일

### 기존 근거로 진행

- [ ] **포트폴리오 읽는 순서 정리.** 대표 프로젝트를 기술 상세 표보다 앞에 배치하고, MoleLaw는 팀 개발에서 발견한 문제 → 개인 재구축의 의도 → 책임 분리와 법령 도구 호출 → 검색 평가 순으로 묶습니다. 기간·역할은 도입부 한 곳에 둡니다.
- [ ] **Molecom 관계도 추가.** 환자 → 검사 → Series → 이미지와 검사당 리포트 하나, 리포트의 작성자 참조를 한 그림에 담습니다. Oracle 검사 키를 MySQL 리포트가 논리적으로 참조하는 관계를 표시합니다.
- [ ] **실제 구동 영상 검토.** MoleLaw의 질문 → 답변 → 출처 확인을 보여주는 짧은 구간을 우선 고릅니다. Molecom 영상은 검사 목록 → 영상 조회 → 리포트 확인이 보이는 구간을 검토합니다. 팀 개발 당시 영상이라면 촬영 시점과 버전을 표시하고, 공개 전 환자 식별정보·계정·내부 주소 노출 여부를 확인합니다.
- [ ] **지원 문서 대조.** 포트폴리오의 역할·기간·측정 범위를 기준으로 README 요약과 이력서의 세 항목을 대조하고, 링크를 확인합니다.

### 본인 설명을 받아 보강

- [ ] **AI Diary 우선.** 로그인과 상담기관 검색·수집 중 직접 방향을 정한 작업은 무엇이었는지, 검색 조건이나 월 단위 수집 주기에 어떤 요구가 있었는지 확인합니다.
- [ ] **Molecom 협업.** 리포트 보존 논의에서 본인이 제안하거나 우려한 지점, 여러 검사와 Series 조회를 수정한 뒤 어떤 방식으로 확인했는지 기록합니다.
- [ ] **MoleLaw 회고.** 검색 평가에서 예상과 달랐던 결과와, 그 결과를 보고 실제로 바꾼 선택이 있었는지 확인합니다. 도구 호출 전후의 효과는 비교 결과가 있을 때 추가합니다.

지원 공고가 생기면 요구 역량에 맞춰 이력서의 지원동기와 사례 순서를 조정합니다.
